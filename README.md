# proview-analytics

Админка и API срезов **ProView** поверх базы-агрегатора ClickHouse (`proview_agg`). Показывает KPI с изменением к прошлому периоду, динамику любой метрики с разрезом, воронку вовлечения, тепловую карту по дням недели и часам и детальный срез по баннерам, местам, странам и устройствам.

Часть платформы: [документация](https://github.com/DemonIngvi/proview-docs) · [развёртывание](https://github.com/DemonIngvi/proview-deploy).

## Возможности админки

- Фильтры: период (час / 24 ч / 7 / 30 / 90 дней / свой), шаг (авто / минута / час / день), метрика, разрез, баннер, место, страна, устройство, часовой пояс, автообновление.
- Состояние хранится в URL, поэтому любой вид можно отправить ссылкой.
- Светлая и тёмная темы. У каждого графика есть табличное представление.
- Цвет закреплён за сущностью, а не за рангом, и не меняется при смене фильтров. Палитра проверена на различимость при нарушениях цветовосприятия.
- Без сборки: ES-модули и ECharts лежат в репозитории (`web/static/vendor`), CSP `default-src 'self'`.

## Метрики

Все производные метрики считаются на сервере по одному определению:

| Метрика | Формула |
|---|---|
| CTR | клики / показы |
| Видимость | видимые показы / показы (IAB: ≥ 50 % площади ≥ 1 с) |
| Доля наведений | наведения / показы |
| Ср. время наведения | Σ длительность наведений / наведения |
| Ср. активное время | Σ активное время / показы |
| Уникальные посетители | `uniqMerge` по показам (HyperLogLog, погрешность ~1–2 %) |

## API

Все запросы по `GET`. Общие параметры: `from`, `to` (RFC3339, `YYYY-MM-DD[THH:MM]` или unix), `tz`, `granularity`, а также фильтры `banner`, `placement`, `country`, `device` (значения через запятую).

| Путь | Что возвращает |
|---|---|
| `/api/v1/summary` | итоги периода и равного по длине предыдущего |
| `/api/v1/timeseries?group_by=banner&top=8` | ряды с заполненными пропусками по бакетам, топ-N по показам |
| `/api/v1/breakdown?dimension=country&limit=20` | срез по измерению |
| `/api/v1/heatmap` | день недели × час в заданном поясе |
| `/api/v1/dimensions` | значения для фильтров (имена баннеров берутся из banner-service) |

Защита ClickHouse:
- только параметризованные запросы, идентификаторы из белого списка;
- ограничение диапазона по шагу (минута ≤ 48 ч, час ≤ 93 дня, день ≤ 2 года);
- `max_execution_time`;
- кэш ответов (`CACHE_TTL`) со склейкой одинаковых одновременных запросов (singleflight);
- пользователь ClickHouse только для чтения с правами `SELECT` на `proview_agg`.

Короткие и свежие диапазоны читаются из минутных агрегатов, длинные — из часовых. Начало интервала округляется вниз до бакета.

## Конфигурация

| Переменная | По умолчанию | |
|---|---|---|
| `CLICKHOUSE_ADDRS`, `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD` | —, `default`, — | используйте пользователя только для чтения |
| `QUERY_TIMEOUT` | `10s` | `max_execution_time` |
| `CACHE_TTL` | `15s` | |
| `ADMIN_USER` / `ADMIN_PASSWORD` | `admin` / — | Basic-auth |
| `AUTH_DISABLED` | `false` | `true` только за SSO-прокси (oauth2-proxy на ingress) |
| `BANNER_ADMIN_URL` / `BANNER_ADMIN_TOKEN` | — | имена баннеров в подписях |

## Разработка

```bash
make test && npm test        # Go и JS (node --test) unit-тесты
PROVIEW_TEST_CLICKHOUSE=localhost:9000 PROVIEW_TEST_CLICKHOUSE_PASSWORD=pw make test-integration
make lint docker helm-lint
```

`testdata/*.sql` — копия схемы из `proview-event-ingester`. Интеграционный тест прогоняет все запросы на ней и ловит расхождение контракта.
